# AGENTS.md

Django 5.2 (Python 3.13) timetable app for COET. The only active app is `core`; `allocation` is a stub (empty models, no migration). Project templates live in `templates/` (global `DIRS`) with shared partials under `templates/core/`.

## Commands

All from repo root (`E:\COET_TIMETABLE\Coet_timetable`). Use `.venv\Scripts\python.exe` — a second venv `venv/` also exists, both Python 3.13.

- Dev server: `.venv\Scripts\python.exe manage.py runserver`
- Sample data import requires `--file` (README omits the flags), and order matters:
  ```
  manage.py import_semesters --file sample_data/semesters.xlsx
  manage.py import_programmes --file sample_data/programmes.xlsx
  manage.py import_student_groups --file sample_data/student_groups.xlsx
  manage.py import_programme_courses --file sample_data/programme_courses.xlsx
  manage.py import_venues --file sample_data/venues.xlsx
  manage.py import_master_timetable --file sample_data/master_timetable.xlsx --semester 1
  manage.py import_workshop_allocation --file sample_data/workshop_allocation.xlsx --semester 1
  manage.py import_td_allocation --file sample_data/td_allocation.xlsx --semester 1
  ```
  `create_sample_data.py` regenerates those Excel files and prints the full command sequence. Import commands `exit(1)` on any row error. Master-timetable imports require `--semester` (the PK of the target `Semester` — it is never auto-created) and support a `--dry-run` flag (reconcilies/validates but writes nothing; also prints `DRY RUN — no records were written.`).
- Test suite: `.venv\Scripts\python.exe manage.py test` runs 100 tests in `core/tests.py` (import reconciliation/idempotency, adaptive alias/reshape imports, CSRF-enforced CRUD responses for htmx and plain posts, sidebar active-nav, upload view, PDF/timetable exports). Uses an isolated test DB — `db.sqlite3` is never touched. Keep uses of `make_xlsx` (module function) rather than a per-instance `_xlsx`.

## Conventions when adding features

- CRUD is hand-rolled and repetitive in `core/views.py`: one resource = list + create + edit + delete + detail views, 5 URL patterns (`core/urls.py`), and templates. Copy an existing block (e.g. venues) instead of writing class-based views.
- List views filter on `?q=` plus resource-specific filters, and render the partial `core/_table_and_cards.html` when the `HX-Request` header is present, otherwise the full `core/list.html`.
- Write views return `HttpResponse("")` with an `HX-Trigger` header on success (`close-modal,refresh-table`, plus `refresh-detail` for edits) via the shared `_write_response(request, trigger, redirect_name, *args)` helper, which also does a plain `redirect()` for non-htmx POSTs so saves never appear to hang. The browser modal/slide-panel JS in `templates/base.html` is wired to those triggers and auto-refreshes — keep using them.
- Every mutating view (create/edit/delete for the 8 CRUD resources, session group add/remove/clear, lecture-group assignment, import uploads) records an `ActivityLog` entry via the `_log(action, message, resource="", target="")` helper in `core/views.py` (uses `LogAction` choices). Keep logging in any new mutating view. The sidebar's Activity Log section renders the latest entries via the `{% activity_logs N as logs %}` tag and `log_badge_cls` filter in `templates/partials/sidebar.html`; each entry links to the dashboard with `?log=<pk>`, and `dashboard()` reads `request.GET["log"]` to display it in a dismissible panel whose Cancel button links back to the bare dashboard (no `?log=`).
- Frontend is htmx (2.0.4) + Alpine.js + Tailwind, all loaded from CDNs (requires internet, no bundler). Form templates post with `hx-target="#modal-content"`. After innerHTML swaps, `base.html` runs `Alpine.initTree` on the swapped element (via `htmx:afterSwap`) — page-level Alpine state lives on `<body x-data>` so it must be hoisted there, not on a swappable child. Sidebar active state comes from the `nav_section`/`active_cls` tags in `core_tags.py` (derived from `request.resolver_match.url_name`); per-view `NAV` context keys no longer exist.
- Style form widgets with the existing `INPUT_CLS` / `SELECT_CLS` constants in `core/forms.py`. Session create/edit uses the inline `SessionGroupFormSet`.

## Timetable view & PDF exports

- On-screen timetable (`/timetable/`, view `timetable_view`) and the PDF exports both build on `core/timetable_pdf.collect_entries` (sessions + workshops + TDs for a programme, or `collect_group_entries` for a single group). The on-screen view uses `core/timetable_grid.build_day_time_grid` (DAYS as rows — always the full Monday..Friday range with full weekday labels, plus any weekend days present; hourly TIME columns each labelled in the master-timetable format e.g. `07:00-07:55` — on-screen slot labels are built by `_screen_slot`, while the PDF/classic grid keeps the plain `07:00-08:00` labels from `_slot`). Each day is a vertical band of sub-rows (lanes, `_partition_lanes`): a session that spans several hourly slots is drawn as ONE cell merging those columns (`colspan` derived from every covered hour, including partial hours), and overlapping sessions sit on separate lanes instead of being sliced into one box per hour column. Rendered through `templates/core/_timetable_grid.html` with one plain-text entry box (`templates/core/_activity_card.html`) per entry — the box reads exactly like the UDSM Excel grid cells: `"Type, Start-End, Day"` / `Course: CODE` / `Venue: VENUE` / `Assigned groups: GROUPS` (left blank when a session has no assigned groups). The master timetable entries are the source of truth: ungrouped sessions still appear. The PDF exports use `core/timetable_grid.build_time_day_grid` (TIME rows / DAY columns, merged via `rowspan`). DAYS-only filter on `Day` choices; fills via `fill_color`; PDF rendering is `render_programme_timetable`/`render_group_timetable` (reportlab `SimpleDocTemplate` — the on-screen/template shading matches the PDF colours).
- Export URLs: `export/` (export picker page), `export/programmes/<pk>/timetable.pdf/` (name `programme-timetable-export`), `export/groups/<pk>/timetable.pdf/` (name `group-timetable-export`); also `programmes/<pk>/timetable.pdf/` (`programme-timetable-pdf`), `timetable/` (`timetable`), `timetable/groups/` (`timetable-groups`).
- PDF exports accept `?semester=<pk>` & `?year=<n>`; without `semester` they fall back to the latest semester that actually has data (`_latest_semester_with_data` in `core/views.py`).

### Folding duplicate sessions (all PDF exports)

`fold_same_sessions(entries)` in `core/timetable_pdf.py` is the single place the "same day + same time + same course is one session" rule lives; `fold_for_display(entries, all_group_codes)` adds the group list and cell text on top. **All three PDF exports call it** (`render_udsm_master_timetable` via `_merge_master_entries`, plus `render_programme_timetable` and `render_group_timetable`); the on-screen timetable view deliberately does **not** yet, so `collect_entries`/`collect_group_entries` still return one entry per group there.

- **A slot is a day plus the set of hours covered — not the clock strings.** `_slot_of` keys on `frozenset(entry["hours"])`, which is what lets a `09:00-12:55` placeholder and a `09:00-13:00` allocation be recognised as one slot. Keying on the raw `start`/`end` strings is exactly what let the two be drawn as separate blocks.
- **One daily workshop slot is ONE session, whoever attends it.** `_identity_of` identifies a workshop by its slot alone (`("workshop", "")`), not by which craft it is, so Carpentry + Welding + Masonry at Monday 09:00-13:00 collapse into a single block reading `Workshop` with every attending group listed. Splitting them per craft was tried and rejected: it turned one session into three and buried the group list. Technical drawing keeps its course, so two genuinely different TD courses in one slot still read separately.
- **A placeholder course code names no course.** `PLACEHOLDER_COURSE_CODES` covers `WORKSHOP`, `TD`, `TECHNICAL DRAWING` and friends; such a session is dropped when allocations actually describe its slot, and **kept** when they do not (dropping it would silently lose a real class).
- **An `ME101` practical and the `ME101` technical drawing are one session.** A session whose course a technical-drawing allocation already covers in the same slot folds into that block. Note the asymmetry: workshop coverage is slot-wide (`has_workshop`), while TD matches on course (`td_courses`).
- **Two different session courses in one slot are never merged.** For reference, the master block count went 200 → 226 while per-craft workshop splitting was briefly in place, and back to ~194 once workshops went slot-wide.
- **The assigned-groups line is emphasised: blue, bold and italic.** `GROUPS_STYLE` in `core/timetable_grid.py` is the single source (`#0b4f9e` on `Helvetica-BoldOblique`). The line is identified **by matching the entry's own `groups` value**, not by assuming it comes last, so it survives reordering and works for a session (groups inside its label), a technical drawing (same) and a workshop (groups appended as its own line). `ALL` counts as a group list. The master export draws line by line with `drawString`, so `_pack` carries an `(is_groups)` flag through wrapping; the classic exports go through `cell_markup()` / `time_day_grid_to_table(..., markup=True)`, which is why `_cell_markup` is gone -- markup is now built already-escaped and must **not** be escaped twice.
- **`_master_cell_text` delegates to `_entry_lines`.** It used to carry its own copy of the field order and silently drifted (it kept omitting the workshop time). Do not reintroduce a second implementation of the cell text.
- **Every block states its time, workshops and technical drawings included.** `_time_span` gives `08:00-11:00`; a period-only workshop from the raw matrix workbook has no clock times of its own, so no line is invented for it. A merged workshop or TD block drops the venue and course (they would swamp the cell) but keeps type, time and groups, in the same order as a taught session.
- **A whole-cohort LECTURE reads `ALL`.** `_WHOLE_COHORT_LECTURES` is `CL111`, `MT161`, `MT171`, `ME101`, `SC121`, and `_WHOLE_COHORT_LECTURE_PREFIXES` is `("DS",)`, covering `DS114`, `DS115`, `DS115_COET` and any other DS course. **Lectures only** -- these same courses run per-group tutorials and seminars (CL111 alone has ~24 seminars) which must keep naming their own groups, so `_is_whole_cohort_lecture` checks the activity type as well as the course code. `ALL` is drawn as the groups line and emphasised, not left implicit. A lecture with no `SessionGroup` links at all still reads `ALL` rather than a blank line.
- Merging is by first-seen order and never reorders the week. Groups are de-duplicated in first-seen order and rendered compacted (`_compact_group_codes`), or as `ALL` when they cover every known group.

### All-programmes (master) export

`export/all-programmes/timetable.pdf/` → `render_udsm_master_timetable` builds a **different** layout from the two grid exports above: **A4 landscape**, one horizontal band per weekday stacked down the page, each band a narrow day-label column plus one column per printed hour. The bands are hand-drawn by `_DayFlowable` (a `Flowable`), not by a reportlab `Table`. A3 was tried and rejected: 1191pt of width for thirteen short hour columns meant the reader had to scroll sideways at 100% zoom. Keep the page at A4 landscape and the grid within the 8mm side margins.

- **Blocks are packed, not gridded.** `_pack` lays blocks down in `_stack_order` order (shortest session first, then start time) and drops each onto the *lowest* position free across every hour column it covers — including down into a hole left by a narrower neighbour. The narrow blocks therefore keep the top of the band, the wide ones sink into the gaps, and the band is as short as the data allows. Never overlap: the placement test is exact, and `test_boxes_never_overlap_within_a_day` guards it.
- **`BLOCK_GAP` is reserved by the packer, not faked by the renderer.** `_lowest_free` offers `run_top + BLOCK_GAP` as candidate positions and records occupancy as the plain logical span `[top, bottom]`, so a packed block's drawn rect *is* its logical box and the gap you see between two stacked sessions is exactly `BLOCK_GAP`. Drawing the box inset vertically as well would halve the visible margin — the inset is horizontal only, keeping blocks off the column lines. Each band also carries a trailing `BLOCK_GAP` margin (`height = content_height + BLOCK_GAP`), which is what puts the same clear space between the last block of one day and the first block of the next.
- **One rule per band, in the middle of that margin** (`RULE_WIDTH`, drawn at `rule_y = margin / 2`). Consecutive bands carry no spacer, so that single rule separates two days — one line, equal clear space either side, no gutter, and no band ever hangs open-ended. A band's top edge is closed by whatever sits above it (the neighbouring day's rule, or the hour header painted by `_draw_master_header`, which sits flush on the frame top so it also closes the first band on each page). At a page-break seam the margin can be squeezed to zero, and `rule_y` follows it to 0.
- **A day fills the page it starts on.** `split` walks the candidate cut lines (always some block's own `top`) lowest first and takes the highest one that fits `avail_height`, so a day starts on a partly-used page instead of jumping to the next one. Returning `[]` (not `[self]`) when not even the first block fits is what makes reportlab carry the whole day to a fresh page; returning `[self]` there raises `Splitting error`.
- **A cut line may cross a block — but only in a column nothing else shares across the break.** `_clean_cut_levels` yields the lines where, in every hour column the line actually crosses, the lowest block above ends before the highest block below begins. The tempting stricter rule ("no block is crossed at all", i.e. `content <= level`) is wrong: a densely packed day is a *staircase* where the tallest block in every prefix runs past the next line, so NO line qualifies, the day gets no split at all, and it jumps to a fresh page with the space below left empty. Do not reintroduce that rule. Two related traps: a column the line does not cross is irrelevant (a lone block may span the break), and a rejected line must `continue`, never `break`, because a higher line is often clear.
- **A day's name is written exactly once, on the chunk holding the day's vertical midpoint.** Ownership is settled in `split` and handed straight down via `label_here`: a chunk that does not own the name must pass `False` to *both* children (`self.label_here and not first_owns` for the continuation — plain `not first_owns` re-grants the name and writes it twice). `_label_offset` clamps the midpoint into the chunk's content, so a midpoint landing in the clear space at a seam still sits against the blocks. Every chunk keeps its own bordered day-label column, so a day carried over from the previous page never looks cut off down its side.
- **Cell metrics** (`CELL_SIZE`/`LEADING`/`PAD_Y`): 6.5pt text at 1.26x leading — 6.5pt matches the classic A4 export, and the leading is deliberately loose so a session's fields read as separate lines. Margins are sized to `HEADER_MARGIN`/`FOOTER_MARGIN` so the frame starts directly under the hour header and ends directly above the footer.
- **Header and footer are painted on the canvas**, not added to the element list, so both repeat on every page. `_draw_master_footer` writes `Generated from <portal> on <date>` with the portal name as a live link (`portal_url`, passed by `all_programmes_timetable_pdf` as `request.build_absolute_uri("/")`) plus `Page N`. A `Link` annotation lives in the page object, not the content stream, so test for it with `/URI (`, not by searching decoded text.

## Data model / importers

- `core/importers.py` returns an `ImportResult` (created/updated/skipped/errors/conflicts, plus reconciliation fields). All importers are header-flexible: `_match_col` matches columns case/punctuation-insensitively against per-importer alias lists (e.g. `course_code`/`course code`/`course`, `venue`/`room`, `capacity`/`seats`, a single `time` range column such as `09:00-12:00` is split via `_split_range`). Missing *required* columns are reported once with the actual headings found. Master-timetable import (`reconcile_master_timetable`, `import_master_timetable_from_excel`) is idempotent, requires a valid `Semester` passed explicitly (blocks with a clear error when `semester_id` is `None` — it is never guessed), auto-creates missing venues with capacity 0 on real imports (not dry-run), expands the legacy group code `ALL` via `ProgrammeCourse`→programme→`StudentGroup` (unresolvable ALL rows become conflicts, never silently dropped), reports missing courses/groups/venues, and after writing (real import only) automatically attaches every programme group that studies the course to each LECTURE session via the shared `assign_lecture_groups(semester)` helper (same as the manual "Assign Lecture Groups" action on the sessions list; counts land in `result.lecture_sessions_processed`/`lecture_groups_linked`/`lecture_groups_existing`/`lecture_skipped_courses`). Comma-separated course codes in one cell are split into separate sessions (`_split_csv`); comma-separated venues are NOT split (kept verbatim as the venue name). The web upload form asks for the target semester for master-timetable (`"semester": "required"` in `IMPORT_TYPES`) and makes it optional (auto-detect) for workshop/TD. Workshop/TD imports use `update_or_create` on a full natural key with `defaults={}` so re-imports are no-ops. All session/workshop/TD imports target a `Semester` by PK (`--semester`); `None` means auto-detect (workshop matrix from the workbook title — auto-creates the detected semester when missing; flat files fall back to semester 1). `import_programme_courses_from_excel` resolves the programme by code then exact name, and auto-creates a missing programme from its full name (`_derive_code` builds a code from significant-word initials, e.g. `BSc. in Chemical and Processing Engineering` → `CPE`; numeric suffix on collision), reported via `result.programmes_created` (rendered on the import result panel). `import_td_allocation_from_excel` also accepts the pivoted Day/Time/Group/Venue layout: day/time/venue are forward-filled over merged-cell blocks (`_fill_down`) and a `time` range is split; a `course_code` column is still required (clear error otherwise).
- Workshop import accepts BOTH formats based on a content sniff (`core/workshop_parser.py`): the legacy flat columns (`course_code, group_code, day, start_time, end_time, venue`) and the raw university Workshop Schedule matrix workbook (GROUPS/POSITION/SCHEDULE/KEY layout) parsed by `parse_workbook` → `WorkshopRecord` intermediates (`reconcile_workshop_workbook` = dry preview; `import_university_workshop_workbook` = write, `--dry-run` supported). The flat importer accepts TWO flat layouts detected from the headers: FORMAT A (`course_code, group_code, day, start_time, end_time, venue`) uses the provided course_code; FORMAT B (`group_code, day, start_time, end_time, venue`) derives `course_code` from the venue cell (e.g. `Electrical` → course_code `Electrical`); blank course_code cells in FORMAT A fall back to the venue too. Neither layout present → a clear `Invalid workshop format` error listing the required columns. Both are idempotent via `update_or_create` on the full natural key. The matrix read derives course_code/workshop from the workshop category, day+`time_period` from the KEY legend positions (no invented clock times → `start_time`/`end_time` are NULL), week_start/week_end from the contiguous week runs per section, and creates the referenced `Semester` from the workbook title when missing; group codes without a matching `StudentGroup` are reported, never created. Raw stray cells (e.g. `Q18=4`) land in `result.unrecognized_cells`.
- `core/models.py`: Semester (unique year+sem), Programme, StudentGroup, ProgrammeCourse, Venue, Session, SessionGroup (through M2M), WorkshopAllocation, TechnicalDrawingAllocation, ActivityLog (`LogAction` choices CREATE/UPDATE/DELETE/IMPORT/ASSIGN/REMOVE). Activity/day are stored as UPPERCASE `TextChoices` (`LECTURE`, `MONDAY`, ...).
- SQLite (`db.sqlite3`, gitignored). After model changes run `makemigrations core` and `migrate`.

## Gotchas

- `manage.py check` reports `staticfiles.W004` because `static/` doesn't exist but is in `STATICFILES_DIRS`. Harmless — all styling comes from CDNs.
- `settings.py` holds local-only, uncommitted LAN IPs in `ALLOWED_HOSTS` (172.16.185.226, 192.168.100.6) — don't strip them.
- README is partly stale: reportlab (timetable PDFs in `core/timetable_pdf.py`) IS used now, but weasyprint is installed and unused.
- `core/templatetags/core_tags.py` defines `get_attr`, `time_short` and `activity_label` (maps variant spellings to the canonical Lecture/Tutorial/Practical/Seminar/Workshop labels) filters, plus the `nav_section`/`active_cls` sidebar tags used by `templates/partials/sidebar.html`.
